# Google Drive 2026 시안 DB 감사 및 재구축 기준

작성일: 2026-09-02  
대상: Google Drive `2026(기획안)` 계열 28개 장축 시안

## 결론

현재 결과가 드라이브 시안과 달랐던 주원인은 고객 정보량 부족이 아니다.

1. 고객 답변의 서로 다른 의미가 `features`, `evidence`, `references`로 합쳐졌다.
2. 제품 이미지는 파일 개수만 확인되었고 색·형태·라벨·재질·브랜드 인상은 분석되지 않았다.
3. 기존 로컬 레퍼런스 DB는 28개 중 14개만 기록하고 5개의 일반 문장만 보유했다.
4. 4개 디자인 방향은 상품과 무관한 고정 템플릿이었다.
5. 최종 생즙연구소 페이지는 분석 결과를 읽지 않는 정적 HTML이었다.

따라서 질문 수를 무작정 늘리는 대신 구매 메시지 우선순위, 사실과 희망의 구분, 시각 정체성, 레퍼런스의 선호·비선호를 분리하여 받아야 한다.

## 드라이브 시안의 변하지 않는 골격

- 전체 문서는 좌측 제작 지시 / 중앙 상세페이지 세로 구성 / 우측 디자인·조판 레퍼런스의 3열 구조다.
- 좌측은 제품 보유 수량, 촬영 컷 수, 구도, 렌즈·카메라, 조명, 배경, 소품, GIF 여부, 기존 이미지 사용 가능 여부를 기록한다.
- 중앙은 최종 디자인이 아니라 실제 제작 순서를 확인하는 회색 와이어프레임이다. 섹션 번호, 제목, 설명, 사진 자리, 정보 그래픽, 사용법, 구성·스펙·FAQ까지 한 흐름으로 연결한다.
- 우측은 링크만 놓지 않는다. 각 레퍼런스에서 가져올 구조, 타이포 위계, 색, 사진 사용법과 복제 금지 요소를 문장으로 분리한다.
- 한 섹션의 하단은 다음 섹션의 이유가 되어야 하며 단절된 감성 사진을 삽입하지 않는다.
- 고객 누끼는 제품의 정체성을 분석하는 1차 증거다. 실제 페이지에서는 연출 사진의 기준으로 우선 사용하고, 누끼 자체는 필요할 때만 마지막 제품 정보 구간 등에 제한적으로 사용한다.

## 상품군별 관찰 패턴

### 음식·음료

- 도입: 실물 제품과 원재료·질감·온도감을 함께 보여주고 제품명과 구체적인 한 가지 구매 이유를 배치한다.
- 전개: 맛·원재료 → 제조·배합 사실 → 음용·섭취 장면 → 사용·보관 → 구성·제품 정보·FAQ.
- 촬영: 제품이 없는 감성 컷은 배제한다. 정면 히어로, 원재료와 제품, 따르기·음용, 내용물 매크로처럼 역할이 다른 최소 4컷을 기본으로 한다.
- 금지: 검증되지 않은 함량·효능·원산지·가격을 핵심 메시지로 만들지 않는다.

### 화장품·퍼스널케어

- 도입: 피부·모발·사용 부위의 구체적 고민 또는 확인 가능한 효익.
- 전개: 고민 → 제품 해결 방식 → 제형·사용감 → 성분·시험 근거 → 사용 장면·방법 → 추천 대상·옵션·주의.
- 촬영: 패키지 히어로, 제형 매크로, 도포·사용 동작, 사용 부위, 구성·정보면. 전후 비교는 증빙이 있을 때만 사용한다.
- 금지: 이미지 생성으로 용기·라벨을 재설계하거나 임상·저자극을 만들어내지 않는다.

### 기기

- 도입: 제품 실물과 핵심 기능 하나를 같은 화면에서 이해시킨다.
- 전개: 사용 문제 → 해결 구조 → 주요 기능·모드 → 사용 환경 → 설치·앱·관리 → 크기·스펙·안전·서비스.
- 촬영: 제품 3면, 실제 설치 공간, 손과 사용 동선, 재질·포트 매크로, 크기 비교.
- 금지: 인증·성능·배터리·소음·전력을 추정하지 않는다.

### 건강기능식품

- 도입: 섭취 대상과 인정된 기능성 범위를 먼저 확정한다.
- 전개: 대상·상황 → 기능성 원료·함량 → 섭취법 → 인증·시험 → 휴대·구성 → 주의사항.
- 금지: 질병 치료, 의학적 효과, 확인되지 않은 후기·수치.

### 기타제품

- 굿즈는 소장 가치·패키지, 의류는 핏·소재·사이즈, 도구는 사용 목적·안전·내구성을 우선한다.
- 일반 제품은 장식보다 구매 결정 요소를 먼저 찾고 그 요소에 맞는 촬영과 정보 구조를 선택한다.

## 고객 질문 영향도

### 결과를 크게 바꾸는 필수 질문

1. 첫 화면에서 구매자가 가장 먼저 알아야 하는 한 가지.
2. 두 번째와 세 번째로 이해해야 하는 내용.
3. 고객이 구매 직전 망설이는 이유와 이에 답할 실제 근거.
4. 강조할 내용과 의도적으로 힘을 뺄 내용.
5. 제품 이미지에서 반드시 유지할 색·형태·재질·라벨·브랜드 인상.
6. 참고 페이지별 좋아하는 점과 싫어하는 점.
7. 실제로 확보한 증빙과 아직 희망·추정에 불과한 표현.
8. 촬영 가능한 제품 수량·상태와 필요한 장면.

### 보조 질문

- 원하는 분위기, 판매 채널, 가격·옵션, 리뷰 키워드, SEO 키워드.
- 보조 질문은 핵심 메시지와 사실을 덮어쓰지 않는다.

### 제거 또는 후순위화

- 고객에게 완성형 첫 문장을 쓰게 하는 질문.
- 고객이 8개 추상 스타일 중 하나를 고르면 전체 디자인이 결정되는 방식.
- SEO 키워드를 디자인 레퍼런스로 취급하는 방식.

## 생성 전 통과 조건

- 사실, 고객 희망, 관리자 해석, 생성기의 가설이 각각 분리되어 표시된다.
- 제품 시각 분석이 수행되지 않았으면 `시각 분석 미실행`으로 남기고 추정하지 않는다.
- 레퍼런스는 링크 수가 아니라 적용 요소와 금지 요소까지 기록한다.
- 네 방향은 색만 바꾸지 않고 메시지, 레이아웃, 촬영, 정보 밀도와 섹션 흐름이 달라야 한다.
- 선택된 방향은 3열 기획안 구조로 확장되고, 정적 샘플 페이지로 우회하지 않는다.

## 실제 앱 통합 테스트에서 추가로 발견한 문제

- 기존 관리자 라우팅은 고객사명에 `생즙연구소`가 포함되면 제품명과 무관하게 클렌즈 시안으로 이동했다. 사과주스 같은 다른 제품도 잘못된 시안으로 연결될 수 있어 제품명이 `클렌즈·그린블렌드·베리블렌드`인 경우에만 전용 프로세스를 사용하도록 제한했다.
- 관리자툴은 레퍼런스 14개라고 표시했으나 새 DB와 캐시 갱신 후 28개로 표시되었다.
- 최종 기획안 화면은 저장된 1차 분석을 읽지 않아 선택 방향이 바뀌어도 화면이 동일했다. 이제 `haoGeneratedPlanningDraft`를 읽어 선택 방향명, 제품 시각 기준, Drive DB 버전을 화면에 표시한다.
- 그린 제품에 일반 식품 기본색과 보라색이 섞이던 문제를 확인했다. 관리자 원본 검수 팔레트를 안전 팔레트로 고정하고 네 방향은 색이 아니라 레이아웃·촬영·정보 밀도로 구분한다.
- 동일 URL 캐시로 이전 스크립트가 보이던 문제를 확인해 관련 HTML에 무캐시 지시와 버전 쿼리를 적용했다.

## 2026-09-02 앱 테스트 결과

1. 새 고객폼에서 음식/음료 분류와 메시지 우선순위, 사실·증빙, 시각 정체성, 레퍼런스 의도를 입력했다.
2. 관리자툴에서 신규 `클렌즈 그린블렌드` 접수를 불러오고 내용 검수를 완료했다.
3. 관리자툴의 `1차 시안 자동 생성` 버튼으로 1차 분석 화면을 열었다.
4. 입력 완성도 100%, Drive DB `2026-09-02-drive28-v2`, 3열 유사도 목표 90%, 서로 다른 네 방향과 상위 두 방향을 확인했다.
5. 상위 방향을 선택하고 앱 버튼으로 2차 기획안을 생성했다.
6. 결과 화면 상단에 `APP GENERATED`, Drive DB 버전, 선택 방향명이 표시되고 3열 기획안이 열리는 것을 확인했다.
